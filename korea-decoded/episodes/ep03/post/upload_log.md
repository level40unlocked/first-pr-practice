## Build notes (for whoever picks this up next, cloud or local)
Two real bugs were found and fixed while building this episode — worth fixing upstream in the shared code too, since they'll hit EP.4/EP.5 and any future episode that reuses "icons" or "letters" chart types or Hangul text:
1. **`prototypes/charts.py` `EMOJI_FONT`** is hardcoded to `/usr/share/fonts/truetype/noto/NotoColorEmoji.ttf` (Linux-only path). On Windows this raises `OSError: cannot open resource` inside the "icons" chart type, which silently crashes `episode.py`'s render loop mid-frame — the crash has NO visible stderr in some invocations (buffering), and because the video pipe closes early, ffmpeg's `-shortest` flag happily finalizes a shorter-but-valid-looking mp4, so the output LOOKS fine (plays, has a real duration) but is missing the tail of the segment. This is dangerous: nothing fails loudly. Any screen using `{"type": "icons", ...}` triggers it (used this episode by `SCREENS["why"]` and `SCREENS["os"]`).
   - Local-only workaround used here (did not touch the shared file, since the other session runs this on Linux where the real path exists): `episodes/ep03/_run_episode_win.py`, a thin shim that monkeypatches `charts.EMOJI_FONT` to `C:/Windows/Fonts/seguiemj.ttf` before running `episode.py`. Same pattern applied ad hoc to `thumbnail.py` for its own `EMOJI_FONT`.
   - Real fix suggestion: make `EMOJI_FONT` try a short list of candidate paths (like `newsrig.py`'s `font()` already does for `FONT`/`FONT_FILES`) instead of a single hardcoded Linux path, falling back gracefully. Same for `prototypes/thumbnail.py`'s `EMOJI_FONT`.
2. **`assets/fonts/BlackHanSans-Regular.ttf` is gitignored** (`.gitignore`: `assets/fonts/*.ttf` except `Poppins-Bold.ttf`) and was never fetched to this checkout — `charts.py`'s `letters` chart type (`HANGUL_FONT`) needs it and crashes the same silent-truncation way without it. Downloaded it from `https://github.com/google/fonts/raw/main/ofl/blackhansans/BlackHanSans-Regular.ttf` (same OFL license already documented in `assets/fonts/OFL-BlackHanSans.txt`) directly into `assets/fonts/BlackHanSans-Regular.ttf`. This file is still gitignored (by design, matching Poppins), so **a fresh checkout needs to fetch it again** — worth adding a one-line note to `cast/fetch.sh` or a new `assets/fonts/fetch.sh` so this doesn't bite the next episode too.
3. **Lesson for future parallel segment renders**: `run_segments.sh`'s 7-way-parallel invocation combined with bug #1 made 3 of 7 segments (1, 4, 5 — exactly the ones using `icons`/`letters` screens) come out silently truncated (84%, 57%, 40% of true length) while the other 4 rendered perfectly. Always verify `ffprobe duration` of each `render/ep0N_sM_long.wav` against its matching `.mp4` before concatenating — they must match (wav is the ground-truth audio timeline; mp4 duration should be byte-for-byte proportional, it's never legitimately shorter). This episode's segments 1/4/5 were re-rendered one at a time (sequential, via the Windows shim) after catching the mismatch, and the fever short (`make_shorts.py`, which calls `episode.py` directly and bypasses the Windows shim) hit the same `icons` crash and needed the same one-off re-render through `_run_episode_win.py`.

Chapters/SRT timing in this episode's description and `ep03_en.srt` were computed from the real per-line audio durations (`audio/durations_v1.json` / live mp3 lengths), which is the correct ground truth and matched the final corrected render to within rounding (509.95s rendered vs 510.08s computed) — no issue there, just flagging that my FIRST pass used that same correct math and it was the broken renders (not the math) that disagreed, which is what led to finding bugs #1/#2 above.
